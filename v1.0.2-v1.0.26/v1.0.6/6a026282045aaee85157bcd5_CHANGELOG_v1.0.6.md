## v1.0.6 - 引入 Alembic 数据库迁移工具

> **版本：** v1.0.6
> **日期：** 2026-05-12
> **功能：** 数据库迁移管理
> **问题类型：** 工程化改进（P1）

---

## 一、问题背景

在 v1.0.5 及之前版本中，项目使用 `Base.metadata.create_all()` 自动建表：

```python
# app/main.py
Base.metadata.create_all(bind=engine)
```

这种方式存在以下问题：

1. **无法处理表结构变更**：当模型发生变化时（添加字段、修改字段类型等），`create_all()` 不会自动更新已有表结构
2. **手动改表风险高**：需要手动编写 SQL 或使用第三方工具修改表结构，容易出错
3. **团队协作困难**：无法追踪数据库结构变更历史，多人协作时容易产生冲突
4. **生产环境风险**：没有版本控制的表结构变更难以回滚，一旦出错难以恢复

---

## 二、解决方案

引入 **Alembic** - SQLAlchemy 官方的数据库迁移工具，实现：

- ✅ 版本化的数据库结构变更管理
- ✅ 自动生成迁移脚本（基于模型变更）
- ✅ 支持升级（upgrade）和降级（downgrade）
- ✅ 完整的变更历史记录
- ✅ 团队协作友好（迁移脚本可提交到版本控制）

---

### 2. 初始化 Alembic 配置

执行 `alembic init alembic` 创建以下目录结构：

```

├── README              # Alembic 说明文档
├── env.py              # 迁移环境配置（已修改）
├── script.py.mako      # 迁移脚本模板
└── versions/           # 迁移脚本目录
    └── c0a9aa0c37a5_initial_migration.py  # 初始迁移脚本
alembic.ini             # Alembic 配置文件（已修改）
```

---

### 3. `alembic/env.py` - 配置迁移环境

**关键修改：**

```python
# 导入项目配置和模型
import sys
sys.path.append(".")
from app.config import get_settings
from app.database import Base
from app.models import *  # 导入所有模型

# 使用项目的数据库配置
settings = get_settings()
config.set_main_option("sqlalchemy.url", settings.DATABASE_URL)

# 设置目标元数据（用于 autogenerate）
target_metadata = Base.metadata
```

配置说明：
- 使用项目的 `DATABASE_URL` 配置，与应用程序保持一致
- 导入所有模型，使 Alembic 能够检测到模型变更
- 支持自动迁移脚本生成（`--autogenerate`）

---

### 4. `alembic.ini` - 配置文件

- 注释掉默认的 `sqlalchemy.url`，改为由 `env.py` 动态设置

### 5. 创建初始迁移脚本

执行命令生成初始迁移脚本：

```bash
alembic revision --autogenerate -m "Initial migration"
```

生成的脚本 `alembic/versions/c0a9aa0c37a5_initial_migration.py` 包含：

```python
def upgrade() -> None:
    """创建所有表"""
    # ### commands auto generated by Alembic - please adjust! ###
    op.create_table('users', ...)
    op.create_table('posts', ...)
    op.create_table('comments', ...)
    # ... 其他表
    # ### end Alembic commands ###

def downgrade() -> None:
    """删除所有表"""
    # ### commands auto generated by Alembic - please adjust! ###
    op.drop_table('post_tags')
    op.drop_table('messages')
    # ... 其他表
    # ### end Alembic commands ###
```

### 6. `README.md` - 添加 Alembic 使用文档

新增"数据库迁移（Alembic）"章节，包含：

#### 常用命令

```bash
# 创建新的迁移脚本（修改模型后执行）
alembic revision --autogenerate -m "描述本次变更"

# 升级数据库到最新版本
alembic upgrade head

# 降级到上一个版本
alembic downgrade -1

# 查看当前版本
alembic current

# 查看历史版本
alembic history
```

#### 工作流程

1. **修改模型**（`app/models.py`）
2. **生成迁移脚本**：`alembic revision --autogenerate -m "add xxx field"`
3. **检查生成的脚本**（`alembic/versions/xxx.py`）
4. **执行迁移**：`alembic upgrade head`
5. **验证数据库结构**

#### 注意事项

- 自动生成的迁移脚本需要人工检查，确保正确
- 生产环境执行迁移前建议备份数据库
- 团队协作时，迁移脚本需要提交到版本控制

## 六、迁移脚本说明

### 脚本命名规则

```
{revision_id}_{slug}.py
```

例如：`c0a9aa0c37a5_initial_migration.py`

### 脚本结构

```python
"""Initial migration

Revision ID: c0a9aa0c37a5
Revises: 
Create Date: 2026-05-12 05:18:32.123456

"""
from alembic import op
import sqlalchemy as sa

# revision identifiers, used by Alembic.
revision = 'c0a9aa0c37a5'
down_revision = None
branch_labels = None
depends_on = None

def upgrade() -> None:
    """升级操作"""
    pass

def downgrade() -> None:
    """降级操作"""
    pass
```

### 常用操作

```python
# 创建表
op.create_table('users',
    sa.Column('id', sa.Integer(), nullable=False),
    sa.Column('username', sa.String(length=50), nullable=False),
    sa.PrimaryKeyConstraint('id'),
    sa.UniqueConstraint('username')
)

# 添加列
op.add_column('users', sa.Column('age', sa.Integer(), nullable=True))

# 删除列
op.drop_column('users', 'age')

# 创建索引
op.create_index('ix_users_username', 'users', ['username'])

# 删除表
op.drop_table('users')
```
